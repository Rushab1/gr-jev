## 1. `read_jsonl` cannot read a row that holds U+2028, U+2029 or U+0085

`read_jsonl` (`src/grjev/examples.py`) splits a file into rows with `str.splitlines()`, which splits at these three characters as well as at a line feed. `write_jsonl` writes the three characters unescaped. A row that holds one is split in two, and `read_jsonl` raises a `ValidationError`.

Check: an example with each character in its query was written with `write_jsonl` and read with `read_jsonl`. All three reads raised. None of the 33 processed files of MetaTool, StableToolBench and BFCL holds any of the three characters.

Status: no fix (Rushab, 2026-10-04).

## 2. `jev.ask` saves a response before it validates it

`ask` (`src/grjev/jev.py`) saves the body of a 200 response under `data/cache/jev/` and then validates it against `JevResponse`. A body of an unexpected shape is saved. Every later call with the same request and run number reads the file and raises the same `ValidationError`, until the file is deleted. `ask_claude` (`src/grjev/frontier.py`) parses the CLI output before it saves.

Check: `httpx.post` was replaced by a function that returns status 200 with the body `{"unexpected": true}`. Two calls of `ask` raised a `ValidationError`, and the cache folder held one saved file after each.

Status: valid (Rushab, 2026-10-04). Fixed on 2026-10-05: `ask` validates the body before it is saved, and a test in `tests/test_jev.py` checks that a body of an unexpected shape raises and saves nothing.

## 3. The two check scripts call the model only on their first run

`scripts/check_jev.py` and `scripts/check_frontier.py` use the saved responses. The first run calls the model and saves the answer. Each later run prints the saved answer and calls nothing. `AGENTS.md` says that `check_jev.py` "makes one call to confirm the key works" and that `check_frontier.py` "makes one call per model". A wrong or expired key, a sign-out of the `claude` CLI, or a CLI version other than the pinned one does not change the output of a later run.

Check: with `TYPESAFE_API_KEY` removed from the environment, `check_jev.py` printed the saved answer. For `check_frontier.py` the saved responses of both models were found, and the script was not run.

Status: applied on 2026-10-05 by Claude Code, which took the option that the proposal and the response recommended. Rushab confirmed it the same day: "if it is a health check on the models - then yes, obviously". Both scripts make a new call on every run, saved under the lowest run number that is not saved: 1 Jev call, counted against `JEV_CALL_LIMIT`, and 2 Claude calls.

Jev's `choice` question returns one tool of the list. In the 995 examples of the reliability file no tool of the list is correct. In the 497 examples of the multi-tool file two tools are correct. At the first pass the Metrics table on the dashboard scored both files with accuracy, and the Open tab listed neither case.

Status: decided (Rushab, 2026-10-04), in `docs/plan.md`. A "None" candidate is offered, as the last candidate, on MetaTool's similar-tools, scenario and reliability files and on BFCL. ## 6. The selection-share measure does not start at 0% on the multi-tool file

`docs/plan.md` summarises the share of selections in each fifth of the list as half the sum of the gaps between each share and 20%. The 20% holds when the placements spread the correct tools evenly over the fifths. The 5 placements of one correct tool do that at every list length from 5 to 199 except 6. The 8 orders of two correct tools do not. In a list of 10 tools they put 25% of the correct-tool positions in each of the first, third and last fifths, and 12.5% in each of the second and fourth. A model that selects both correct tools in every order scores 15% on the measure.

Check: the positions were computed from the two formulas of the plan, with position p of N tools counted in fifth ⌈5p/N⌉.

Status: no decision. Proposal (Claude Code): report the measure on the single-tool files, or take each gap against the share of correct tools placed in that fifth. No run is added.

## 7. "CSR in the released order minus mean CSR over the 5 positions" changes two things at once

`docs/plan.md` reads the claim "MetaTool's fixed positions change the score of a model with a position effect" from this difference. A released list and a placement list differ in the position of the correct tool and in the order of the distractors, which the placements shuffle with a seed. In the similar-tools file the released order lists the distractors by falling similarity to the correct tool (`open_items_response.md`, item 4).

The first run also holds a difference that changes the position only: for similar tools, CSR at the first placement minus mean CSR over the 5 positions. For multi-tool it is CSR at the adjacent order at 75%, positions 7 and 8, minus mean CSR over the 5 adjacent orders. CSR in the released order minus CSR at that same placement then shows the effect of the order of the distractors.

Check: read from the rules of the plan. No data is involved.

Status: no decision. Proposal (Claude Code): report both differences. No run is added.

## 8. The similar-tools list and the reliability list of a query share no tool

`docs/plan.md` says that with "None" in both files "each query is tested with the correct tool present and absent, on the same 11 candidates". The two files have the same 995 queries. For each of them, the 10 tools of the similar-tools list and the 10 tools of the reliability list have no tool in common. The similar-tools list holds the correct tool and its 9 nearest tools. MetaTool builds a reliability list from tools outside the 20 nearest to the correct tool.

The measure "share of 'None' answers, with a correct tool in the list and without" compares lists that differ in two ways: whether the correct tool is present, and whether the other tools are near it.

Check: the tool names of the two lists were compared for each of the 995 queries. The number of shared tools is 0 in all 995.

Status: no decision. Possible spare (Claude Code): the similar-tools list without its correct tool, 9 tools and "None", for the 995 queries. Claim: Jev answers "None" when the correct tool is removed and its nearest tools stay. Size: 995 tool lists, about $0.02 at 4 characters per token, an estimate.
