MetaTool is a benchmark for tool selection. An example gives the model a user query and a list of tools, and the model names the tool that should handle the query.

It has 199 tools and 20,614 queries. The tools are ChatGPT plugins from OpenAI's 2023 plugin list, each with a name and a description. Each query is labelled with one tool. ChatGPT and GPT-4 generated the queries from the tool descriptions, and the MetaTool authors verified them by hand.

The repository has five test files. An example in a test file is a query, a tool list and a label. The files differ in how the tool list is built and in what the label is.

The paper scores the four tool-selection files with the Correct Selection Rate (CSR), the percentage of examples where the model selects the labelled tool. It scores tool awareness with accuracy, precision, recall and F1.

  • Similarity is measured between embeddings of the tool descriptions, computed with OpenAI's text-embedding-ada-002.
  • Six scenario lists have 10 tools that the MetaTool authors chose for an occupation or identity: Software Engineer, Finance Staff, Housewife, Students, artists&designers and elders. The other three lists hold the 5, 10 and 15 most popular tools. The paper ranks a tool's popularity by the number of plugins merged into it.
  • Both correct tools in a multi-tool example are among the 15 most popular tools.
  • The prompts in the similar-tools, scenario and reliability files tell the model to answer None if no tool in the list applies. The multi-tool prompt tells it to return two tools.
  • Tool awareness has 520 queries labelled yes (a tool is needed) and 520 labelled no.
  • Each prompt in the similar-tools, scenario and reliability files ends with 5 example queries and their tools, different in every row. Every example tool is in the prompt's tool list. In 488 of the 995 similar-tools prompts and 920 of the 1,800 scenario prompts, one example has the correct tool as its answer. The multi-tool prompts have no examples.

Distributions

  • Similar tools: the 5 queries of a tool get the same list. PolishTool is in its own list and in the lists of 48 other tools, 245 examples. 5 tools are only in their own list. 72 tools are in no scenario, reliability or multi-tool list.
  • Scenario: the 1,800 examples use 9 different lists, each for 100 to 300 examples. 53 of the 199 tools are in at least one of the 9. FinanceTool, PDF&URLTool, ProductSearch and TripTool are in 4 of the 9. Each of the four is in the list of 800 scenario examples and is the correct tool in 80.
  • Multi-tool: both correct tools of all 497 queries are among the 15 tools of the scenario list TopTool_top15. Each of the 15 is a correct tool in 24 to 100 multi-tool examples. In the similar-tools, scenario and multi-tool files together, the correct tool is one of the 15 in 1,432 of the 3,292 examples (43.5%). Each of the 15 is a correct tool in 89 to 168 examples, and each of the other 184 tools in 5 to 65.
  • Distractors: the reliability lists use 89 of the 199 tools, and hacktrack is in 335 of the 995. In the multi-tool lists 67 tools are distractors, and LawTool is one in 171 of the 497. select_10_tools_with_exclusion samples the tools of both files and calls random.seed(48) before every sample.

The 20,614 queries

dataset/data/all_clean_data.csv holds all 20,614 queries in two columns, Query and Tool.

The test files sample from it. The similar-tools file has five queries for each of the 199 tools, 995 in total. The reliability file has the same 995 queries with different tool lists. The scenario file has 20 queries for each tool in a list, and a tool in more than one list has the same 20 in each. Its 1,800 examples have 1,060 different queries, and 265 of them are similar-tools queries. get_query_by_tool in src/prompt/prompt_construction.py calls np.random.seed(48) before every sample. The four files with tool lists have 2,287 different queries in 4,287 examples.

In this study the file is the training data for the fine-tuned model. The test queries are rows of the file. Training on it without removing them puts test queries in the training data.

  • Rows of this file: 993 of the 995 similar-tools queries, 1,797 of the 1,800 scenario queries, and 519 of the 520 tool-awareness queries labelled yes.
  • The 520 tool-awareness queries labelled no come from Self-Instruct (Wang et al., 2022), CommonsenseQA (Talmor et al., 2019) and LIMA (Zhou et al., 2023).
  • The 497 multi-tool queries are in dataset/data/multi_tool_query_golden.json. None of them are rows of all_clean_data.csv.
  • Queries per tool: minimum 12, median 68, maximum 1,122.

List length

Tool lists in the test files have 5, 10 or 15 tools. A longer list keeps the correct tool and adds distractors.

A list built only from MetaTool's tools has at most 199. Jev's choice accepts up to 255 options, and a 255-tool list needs 56 tools from outside MetaTool.

5, 10, 15 199 255
  • Tool descriptions from other datasets differ in form. ToolBench's are API notes such as "Search by name" and "Enter Artist ID", and 960 of the 13,862 in ToolRet's copy (6.9%) are blank.
  • No label says whether a tool from outside MetaTool is incorrect for a MetaTool query.

Fixed positions

In the similar-tools file the correct tool is at position 1 in all 995 examples. In the multi-tool file the two correct tools are at positions 7 and 8 in all 497 examples.

Cause

  • Similar tools: get_10_most_sim searches for the 10 tools nearest to the correct tool's embedding. The correct tool is its own nearest neighbour, and the result is not shuffled.
  • Multi-tool: select_10_tools_with_exclusion calls random.seed(48) for every example and samples the 8 distractors. The two correct tools are appended last, and random.shuffle moves them to positions 7 and 8 every time.
  • Both functions are in src/prompt/prompt_construction.py.

Other files

  • Scenario: each position in a list has 20 examples. All queries in a scenario get the same list in the same order. The counts drop after positions 5 and 10 because 8 of the 9 lists have more than 5 tools and 1 has more than 10.
  • Reliability: the correct tool is in none of the 995 lists.

ToolBench is a benchmark for tool use with real REST APIs. It has 16,464 APIs from RapidAPI Hub, grouped into 3,451 tools, and 126,486 examples. Each example is a query generated by ChatGPT and a solution path. The test set has 1,100 queries.

MetaToolToolBench

Queries20,614, and 497 multi-tool126,486
Test examples5,327 in five files1,100 in six files

A test example is a query and a list of APIs. The label is the subset of the list that the query needs, which the dataset calls the relevant APIs. A MetaTool example has one correct tool, or two in the multi-tool file.

Two later benchmarks contain the same 1,100 test queries. StableToolBench (Guo et al., 2024) keeps the 765 queries that GPT-4 Turbo, Gemini Pro and Claude 2 judged solvable, and adds a virtual API server. ToolRet (Shi et al., 2025) is a tool retrieval benchmark with 35 subsets, and one subset is the 1,100 ToolBench test queries.

This study uses StableToolBench's six test files and cites ToolBench and StableToolBench.

BFCL, the Berkeley Function Calling Leaderboard, is a benchmark for function calling. An example gives the model a user query and a list of function definitions, each with a name, a description and a parameter schema. The model answers with function calls, each a function name with parameter values, or with no call. The label is the list of correct calls, which BFCL calls the ground truth.

BFCL v4 has 13 single-turn test files with 3,641 examples, 4 multi-turn files with 800 examples and 2 agentic files with 255 examples. A single-turn example has one query. A multi-turn example has 1 to 8 turns, and its ground truth has a median of 5 to 6 function calls and at most 35. An agentic example is one question that the model answers by calling web search or memory functions.

VersionReleasedFiles added
v12024-02-26The 7 non-live single-turn files

BFCL marks each example correct or incorrect and reports accuracy for each test file. bfcl_eval/data/README.md calls the check for single-turn files AST evaluation, short for abstract syntax tree. The check compares the model's calls with the ground truth. In irrelevance and live_irrelevance the correct output has no call. In live_relevance the correct output has at least one call, and BFCL does not check whether the call is correct. In v4 the leaderboard's overall accuracy weights the agentic files at 40%, the multi-turn files at 30%, and the non-live, live and irrelevance files at 10% each.

This study uses BFCL as a test-only set. No model is trained on it. Jev's choice question returns one of up to 255 options and no parameter values. For Jev, only the choice of function can be scored.

List length, position, order and format

Each MetaTool test query is run with four kinds of change to the request. Jev is compared with open-weight decision models on each.

FactorWhat changesWhat is measured
List lengthThe number of tools in the listAccuracy at each length
PositionWhere the correct tool sits: start, center or end of the listAccuracy at each position, and how often the model selects each position whether or not the correct tool is there
OrderThe same tools in several shuffled ordersThe share of queries whose answer changes between orders
Prompt formatHow the same query and tools are written in the request, such as separators, casing and spacingThe spread of accuracy across formats, and the share of queries whose answer changes between formats

Fine-tuning and transfer

Two open models are fine-tuned, one on MetaTool's 20,614 queries and one on ToolBench's training set. Each is tested on both benchmarks, next to Jev and the same open model without fine-tuning. No model is trained on both sets. BFCL is a test-only set. The four models are tested on it and no model is trained on it.

Jev as a co-pilot

Question: can Jev reduce the token cost of a frontier LLM on difficult tasks? The frontier LLM proposes each function call, and Jev checks the choice of function before the call runs. A wrong call caught at that point does not cost the tokens of the steps that recover from it. The trajectory corrects itself.

Jev and the frontier LLM select the function on the same examples. Each example falls into one of four outcomes.

OutcomeFor a co-pilot
Both correctNothing to correct
Only the LLM wrongAn error Jev can catch
Only Jev wrongA false alarm
Both wrongAn error Jev cannot catch. Recorded with whether both select the same wrong function.

This is a parallel study to REFLEX (arXiv 2609.26532). In REFLEX, Jev decides first and a strong LLM is called when Jev's confidence is low or text has to be generated. It reports 72.7% fewer strong-model calls on a 100-task benchmark and limited advantage on BFCL.

2023 tool sets

MetaTool's tools are ChatGPT plugins from 2023. ToolBench's APIs were collected from RapidAPI in 2023, and StableToolBench reports that 44.4% of its calls to them succeeded.

The fine-tuned models and the on-device student are baselines on these two benchmarks. The paper makes no claim from them about current tools.

  • The test set is MetaTool's five test files.
