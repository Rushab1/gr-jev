\paragraph{Models.}
We study three decision models. We call Jev (\texttt{jev-1.13.0})~\citep{almeida2026jev} through TypeSafe's API, and Liquid d1 (\texttt{liquid/d1})~\citep{liquidAI2026d1} and GPT-6 Luna Decisions (\texttt{openai/gpt-6-luna-decisions})~\citep{openai2026decisions} through Vercel AI Gateway~\citep{vercel2026models}. Liquid AI and OpenAI publish no version for these two models, and our results refer to the models that the gateway served in October 2026. A request holds a query, an instruction and a list of named choices, each with a description. The answer holds the selected choice, which we call the prediction, and one probability per choice. These Choice probabilities sum to 1~\citep{typesafe2026choice}. We call the highest probability of an answer its confidence. This is not the \texttt{confidence} field of Jev's answer, which TypeSafe computes from the highest probability and the number of choices~\citep{typesafe2026confidence}. Jev and GPT-6 Luna Decisions return probabilities with two decimals, and Liquid d1 with full precision. GPT-6 Luna Decisions can refuse a question and return no probabilities. Jev and Liquid d1 refused none. The three models received the same requests, and we sent each request once. Table~\ref{tab:runs} gives the number of examples and lists of each kind.

\paragraph{Datasets.}
We chose three datasets from different domains, all of which allow multiple correct choices, or have a subset of examples that do. MetaTool~\citep{huang2024metatool} is a tool selection task. The model sees the query and a list of tools and is asked to select the tools needed to solve the query. Its four tool selection subsets hold 4,287 queries. Of these, 995 have one correct tool among tools with similar descriptions, 1,800 have one correct tool among the tools of a scenario, 995 have no correct tool, and 497 have two correct tools. Some queries appear in more than one subset, and the answer to a repeated request counts once for each example.

The distractor setting of HotpotQA~\citep{yang2018hotpotqa} gives a query and up to ten passages, two of which support the answer. While HotpotQA contains training, validation and test sets, we only use the validation set in this study.
 ECtHR, Task~A of LexGLUE~\citep{chalkidis2022lexglue}, is a legal multi-label classification task. Each example
 gives the facts of a case and ten articles of the Convention and it asks the model to select the articles that the case violates. Of its 1,000 test cases, 655 have one violated article, 192 have two to four, and 153 have none. When several choices are correct, the instruction asks for all of them, for example ``Choose every passage in the list that supports the answer to the question.'' Table~\ref{tab:datasets} gives the number of examples of each kind of list.


\paragraph{Identical choices.}
In our first experiment, for every example, we send five identical copies of one of its correct choices. The query and the instruction remain unchanged. Exactly identical copies are rejected by the APIs, hence we name each copy with a random ID. Identical copies are equally correct and equally relevant to the query, so a difference between their probabilities cannot come from their content. To place every copy once at every position, we send each list in its five cyclic permutations~\citep{zheng2024large,pezeshkpour2024large}.

We build these lists for 3,292 MetaTool queries, a seeded sample of 1,000 HotpotQA questions and the 847 ECtHR cases with a violated article, 25,695 lists per model. We report the mean probability of the highest and the lowest copy, the gap between them, and the share of predictions at each position. Under position-invariance and uniformity, we would expect the mean probability of each copy to be 0.20, and the gap to be 0.00.

\paragraph{The gap between correct choices.}
Next, we send the lists as the datasets give them. MetaTool gives 497 queries with two correct tools, and HotpotQA its questions. We send both in their released order. ECtHR gives 192 cases with two to four violated articles. We send each list in its ten cyclic permutations. For each answer, the gap is the highest minus the lowest probability given to a correct choice, and we report its mean. As a reference we use the uniform distribution, which gives each of $n$ choices $1/n$ and prefers none of them. We report the share of lists in which at least one correct choice gets less than $1/n$. To separate this from ranking errors, we also report the share of lists in which every correct choice is above every distractor, and, among those lists, the share in which a correct choice still gets less than $1/n$. These counts use only the released order of the ECtHR lists and leave out the 21 HotpotQA questions whose list has no distractor.

\paragraph{Calibration.}
A model is calibrated when, among the answers to which it gives a probability $p$, a share $p$ is correct. For lists with exactly one correct choice, we define confidence as the highest probability assigned to any choice. For lists with several correct choices, this definition does not directly apply. We therefore convert each list into several yes/no questions, one per choice, based on the benchmarks' format. For example, for HotpotQA we ask ``Does this passage support the answer to the question?'' for every (question, passage) pair. The models respond with a single probability of ``yes''. We report the Expected Calibration Error (ECE)~\citep{naeini2015obtaining,guo2017calibration} over ten bins of equal width, which compares the mean confidence, or the mean probability of ``yes'', with the observed share of correct predictions, or of true ``yes'' labels, in each bin. For the yes/no questions, we also report the ECE without the bin from 0 to 0.1.

\paragraph{Selecting by a threshold.}
Model providers suggest using a threshold to select multiple correct choices~\citep{typesafe2026choice,openai2026decisions}. For example, TypeSafe's documentation includes an example with three choices, two of which are correct, and uses a threshold of 0.25. A threshold $t$ selects every choice whose probability is at or above $t$. In this experiment, we study whether there is a common threshold that selects all correct choices and no distractors across all examples in the dataset.

We start with examples answered both as lists and as yes/no questions, vary $t$ from 0 to 1, and compare the two formats. We define exact set accuracy as the share of examples in which every correct choice is selected and every distractor is rejected. We define recall as the proportion of correct choices above the threshold, and precision as the proportion of choices above the threshold that are correct. We compute precision, recall, and F1 from counts pooled across all examples. We plot exact set accuracy, recall, precision and F1 as functions of the threshold $t$ from 0 to 1.
