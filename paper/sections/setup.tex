\paragraph{Models.}
We study three decision models: Jev (\texttt{jev-1.13.0})~\citep{almeida2026jev} through TypeSafe's API, and Liquid d1 (\texttt{liquid/d1})~\citep{liquidAI2026d1} and GPT-6 Luna Decisions (\texttt{openai/gpt-6-luna-decisions})~\citep{openai2026decisions} through Vercel AI Gateway~\citep{vercel2026models}, which does not take a model version. A request holds a query, an instruction and a list of named choices, each with a description. The answer holds the selected choice, which we call the prediction, and one probability per choice. These Choice probabilities sum to 1~\citep{typesafe2026choice}. We call the highest probability of an answer its confidence. This is not the \texttt{confidence} field of Jev's answer, which TypeSafe computes from the highest probability and the number of choices~\citep{typesafe2026confidence}. Jev and GPT-6 Luna Decisions return probabilities with two decimals, and Liquid d1 with full precision. GPT-6 Luna Decisions can refuse a question and return no probabilities; Jev and Liquid d1 refused none. The three models received the same requests, and we sent each request once, except for the repeat check in the limitations and the 3 runs of the opening example. Table~\ref{tab:runs} gives the number of examples and lists of each kind.

\paragraph{Datasets.}
We intentionally chose three datasets from different domains, all of which allow multiple correct choices, or have a subset of examples that do. MetaTool~\citep{huang2024metatool} is a tool selection task. The model sees the query and a list of tools and is asked to select the tools needed to solve the query. Its four tool selection subsets hold 4,287 queries: 995 with one correct tool among tools with similar descriptions, 1,800 with one correct tool among the tools of a scenario, 995 with no correct tool, and 497 with two correct tools.

The distractor setting of HotpotQA~\citep{yang2018hotpotqa} gives a query and up to ten passages, two of which support the answer. While HotpotQA contains training, validation and test sets, we only use the validation set in this study.
 ECtHR, Task~A of LexGLUE~\citep{chalkidis2022lexglue}, is a legal multi-label classification task. Each example
 gives the facts of a case and ten articles of the Convention and it asks the model to select the articles that the case violates. Of its 1,000 test cases, 655 have one violated article, 192 have two to four, and 153 have none. When several choices are correct, the instruction asks for all of them, for example ``Choose every passage in the list that supports the answer to the question.'' Appendix~\ref{app:lists} gives every instruction. Table~\ref{tab:datasets} gives the number of examples of each kind of list.


\paragraph{Identical choices.}
In our first experiment, for every example, we send five identical copies of one of its correct choices. The query and the instruction remain unchanged. Exactly identical copies are rejected by the APIs, hence we name each copy with a random ID. While this is a limitation, it still clearly demonstrates that semantically (exactly) equivalent choices receive widely different probabilities. Appendix~\ref{app:lists} shows the list for the question of Table~\ref{tab:example}. To ensure that every almost identical choice is treated the same, we send each list in five cyclic permutations~\citep{zheng2024large,pezeshkpour2024large}, ensuring that every copy appears once at every position.

We build these lists for 3,292 MetaTool queries, a seeded sample of 1,000 HotpotQA questions and the 847 ECtHR cases with a violated article, 25,695 lists per model. We report the mean probability of the highest and the lowest copy, the gap between them, and the share of predictions at each position. Under position-invariance and uniformity, we would expect the mean probability of each copy to be 0.20, and the gap to be 0.00.

\paragraph{The gap between correct choices.}
Next, we send the lists as the datasets give them. MetaTool gives 497 queries with two correct tools, and HotpotQA its questions; we send both in their released order. ECtHR gives 192 cases with two to four violated articles; we send each list in its ten cyclic permutations. For each answer, the gap is the highest minus the lowest probability given to a correct choice, and we report its mean. As a reference we use the uniform distribution, which gives each of $n$ choices $1/n$ and prefers none of them. We report the share of lists in which at least one correct choice gets less than $1/n$. To separate this from ranking errors, we also report the share of lists in which every correct choice is above every distractor, and, among those lists, the share in which a correct choice still gets less than $1/n$. These counts use only the released order of the ECtHR lists and leave out the 21 HotpotQA questions whose list has no distractor.

\paragraph{Calibration.}
A model is calibrated when, among the answers to which it gives a probability $p$, a share $p$ is correct. For lists with exactly one correct choice, we define confidence as the highest probability assigned to any choice. For lists with several correct choices, this definition does not directly apply. We therefore convert each list into several yes/no questions, one per choice, based on the benchmarks' format. For example, for HotpotQA we ask ``Does this passage support the answer to the question?'' for every (question, passage) pair. The models respond with a single probability of ``yes''. We report the Expected Calibration Error (ECE)~\citep{naeini2015obtaining,guo2017calibration} over ten bins of equal width, which compares the mean confidence, or the mean probability of ``yes'', with the observed share of correct predictions, or of true ``yes'' labels, in each bin. For the yes/no questions, we also report the ECE without the bin from 0 to 0.1.

\paragraph{Selecting by a threshold.}
Model providers suggest using a threshold to select multiple valid choices~\citep{typesafe2026choice,openai2026decisions}. For example, TypeSafe's documentation includes an example with three choices, two of which are correct, and uses a threshold of 0.25. A threshold $t$ selects every choice whose probability is at or above $t$. In this experiment, we study whether there is a common threshold that selects all correct choices and no distractors across all examples in the dataset.

We start with examples answered both as lists and as yes/no questions, vary $t$ from 0 to 1, and compare the two formats. We define exact set accuracy as the share of examples in which every correct choice is selected and every distractor is rejected. We define recall as the proportion of correct choices above the threshold, and precision as the proportion of choices above the threshold that are correct. We compute precision, recall, and F1 from counts pooled across all examples. We measure the recall of the other correct choices by leaving out the correct choice with the highest probability in each example, which almost any threshold selects, and calculating the share of the remaining correct choices that are selected across all examples. We plot exact set accuracy, recall, precision, F1, and recall of the other correct choices as functions of the threshold $t$ from 0 to 1.

\paragraph{None of the above.}
Following \citet{tam2025none}, we send lists with no correct choice. We build them from examples with any number of correct choices and leave out every correct choice. A list holds either random choices from the dataset that are not in the example's list, or the example's own distractors. We send each list without and with a ``none of the above'' choice. Without it, we report the confidence of the prediction. With it, ``none of the above'' is the only correct answer, and we report the share of predictions that select it.

\paragraph{Other lists.}
We send lists with one correct choice in several orders. For lists with two or more correct choices, we remove the correct choice with the highest probability and compare the probability of the next correct choice before and after the removal.
